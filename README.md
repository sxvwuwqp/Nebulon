# 介绍说明

\# ✨ Nebulon 语言

\#\# 面向 NebulaOS 的零运行时系统编程语言

**Nebulon** 是一门现代静态类型、零运行时的系统级编程语言，专门为裸机自研 **NebulaOS C/C\+\+ 内核** 设计。

它拥有优雅的高级语法，最终编译为兼容 C ABI 的原生机器码 —— **零开销、无 GC、无运行时依赖**，运行性能完全等同于手写原生 C 内核代码。

Nebulon 旨在替代传统繁琐、安全性弱的纯 C 内核开发方式，提供编译期安全校验、自动资源管理、现代化并发语法、零成本元编程能力，在不损失任何底层性能的前提下，大幅提升操作系统内核、驱动与系统应用的开发效率与稳定性。

所有 Nebulon 源码文件统一使用 `.nbn` 作为后缀，配套**Aether Compiler（以太编译器）**完成全链路静态 AOT 提前编译。整套编译体系为100%纯C\+\+自研架构，词法分析、语法解析、AST抽象语法树构建、静态语义校验、内核上下文检测、编译期元编程展开、资源自动插桩优化全部自主实现，仅复用极简LLVM机器码优化后端，无任何开源编译核心依赖。语言语法规范、编译链路、内核适配规则、安全校验体系完全独立自研，彻底摆脱传统C语言编译生态束缚，实现从语言、工具链到操作系统内核的全栈自主可控底层生态。

## 🌌 核心特性

- **零运行时纯静态架构**：无虚拟机、无垃圾回收GC、无系统运行时库、无解释执行逻辑。所有高级语法糖、资源托管逻辑、并发语法、元编程特性均在编译期完整展开降级，最终输出纯原生机器码，运行时零额外开销，性能与手写标准C内核代码完全对齐。

- **内核级编译期静态安全校验**：Aether 编译器内置专属内核上下文状态机校验机制，精准区分内核中断上下文、无堆上下文、任务调度上下文。可在编译阶段主动拦截动态内存滥用、中断阻塞、非法锁竞争、无效任务调度等高危操作，从代码根源杜绝内核死锁、内存崩溃、系统宕机问题。

- **全自动资源生命周期托管**：原生内置 `scope`、`guard`、`taskset` 托管语法，替代传统C语言手动申请与释放资源。自动完成内核锁解锁、设备句柄回收、内核任务归集、作用域资源释放，彻底解决传统内核开发中高频出现的内存泄漏、句柄残留、死锁、任务滞留等工程顽疾。

- **零成本编译期元编程能力**：支持结构体静态反射、字段遍历、类型判别、静态配置绑定、常量迭代计算。所有元数据仅用于编译期校验与代码生成，不打包进最终二进制文件，无任何运行时开销。原生支持 JSON、XML、Protobuf 协议静态解析，无需引入任何第三方依赖库。

- **原生内核并发调度语法**：提供 `launch`、`await`、`parallel` 现代化并发语法，编译后直接精准映射 NebulaOS 内核原生M\-N调度原语、事件多路复用、批量任务调度逻辑，无中间封装层损耗，兼顾代码简洁性与内核原生极致调度性能。

## 📦 开发体验

官方统一发布 **Windows / macOS / Linux 三平台预编译一体化SDK**，彻底颠覆传统系统语言复杂的环境搭建流程。开发者无需下载、安装和配置 C/C\+\+、GCC、Clang、CMake、LLVM 等任何编译依赖，下载对应平台压缩包解压即可使用。SDK内置静态成品Aether编译器、NebulaOS专属链接器、轻量化交叉工具链、内核静态库、全套内核/用户态开发头文件与标准链接脚本，全平台编译规则、优化等级、产物规格完全统一，支持跨平台可复现构建，真正实现开箱即用、零配置、零环境搭建。

标准编译指令（全平台通用）：

- 用户态调试编译：`aether --debug main.nbn -o app_debug`

- 用户态正式发布编译：`aether --release --static-full main.nbn -o app`

- 内核驱动KO编译：`aether --release --target=nebulaos-kernel --no-heap --kmode driver.nbn -o dev_drv.ko`

所有编译产物仅适配 NebulaOS 内核环境，与宿主系统完全隔离，杜绝ABI兼容污染。

## 🛡️ 核心优势对比（VS 传统C语言内核开发）

- **安全性碾压**：C语言无任何编译期内核校验，非法操作运行时直接宕机；Nebulon 内置内核状态机校验，高危操作编译直接报错，从根源规避系统崩溃。

- **工程性更强**：告别C语言手动资源释放、手动锁管理、手动任务回收，全自动托管，杜绝内存泄漏、死锁、任务残留顽疾。

- **开发效率更高**：现代化高级语法、编译期元编程、静态协议解析，无需手写冗余模板代码，底层开发体验大幅升级。

- **性能完全持平**：零运行时、零中间层、零开销封装，最终机器码与标准C内核代码完全等价，无任何性能损耗。

- **跨平台开发统一**：三平台SDK编译逻辑、产物哈希、优化等级完全一致，解决传统C编译跨平台错乱、环境依赖繁杂问题。

## ⚙️ 编译体系规范

Nebulon 采用**纯静态AOT编译机制**，不支持JIT、不支持动态编译、不携带任何运行时动态逻辑，完全适配裸机操作系统内核运行特性。编译全程隔离宿主系统环境，不调用系统GCC、Clang、系统标准库，所有编译依赖全部内置在官方SDK中。

编译产物严格遵循 NebulaOS 内核 ABI 规范、内存对齐规则、段分配逻辑、调度调用约定，产物仅可在 NebulaOS 环境运行，彻底杜绝宿主系统ABI污染与兼容问题。
